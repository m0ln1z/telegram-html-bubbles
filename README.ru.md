# Telegram HTML Bubbles: практическое руководство

[English](README.md) · **Русский**

HTML Bubbles — это интерактивные HTML-виджеты, которые бот отправляет **прямо внутри сообщения** в чате (Telegram 13.2+, Bot API 10.4). В этом репозитории разобрана техническая часть: API, ограничения рантайма и ошибки, которые молча ломают виджет. Есть рабочие примеры.

> Статус (ноябрь 2026): Bot API 10.4 в **бете**. Методы работают только на бета-адресе, детали ещё могут поменяться. Первоисточник — репозиторий Telegram [widget-sandbox](https://github.com/TelegramMessenger/widget-sandbox) (`docs/widget-runtime-profile.md`, `docs/profile-v1.md`, `docs/sdk-v1.md`, `docs/tgw-format.md`).

## Быстрый старт

```sh
git clone <этот репозиторий> && cd telegram-html-bubbles
cp .env.example .env            # вписать BOT_TOKEN от @BotFather
python3 tools/probe.py          # (с экспортированным BOT_TOKEN) покажет, где есть sendWidget
./run.sh                        # создаёт .venv и запускает бота
```

Потом напиши боту `/hello`, `/counter`, `/anim` или `/poll`. Бот использует только стандартную библиотеку Python, так что ставить в venv ничего не нужно.

Чтобы увидеть виджет, получателю нужен **Telegram 13.2+**.

## Сторона бота: API

### Базовый адрес

На обычном адресе `sendWidget` отвечает **`Not Found`**. Метод доступен на бета-адресе:

```
https://api.telegram.org/beta/bot<TOKEN>/<method>
```

Обычный боевой токен там работает. `getMe`, `getUpdates` и остальные методы тоже работают, так что бота можно целиком перевести на этот адрес. `tools/probe.py` проверяет оба варианта. Когда выйдет 10.4, верни `API_BASE` на `https://api.telegram.org`.

### Методы

| Метод | Назначение |
|---|---|
| `sendWidget` | Отправить виджет. Поля: `chat_id`, **`html`** (обязателен), `width`, `height`, `chat_data`, `public_data`, `caption`, `allow_queries`, `is_shared`, `reply_markup` |
| `sendSharedWidget` | Отправить уже существующий общий виджет ещё раз: `chat_id`, `widget_id`, `chat_data` |
| `answerWidgetQuery` | Ответить на запрос виджета: `widget_query_id`, `data` (≤ 1024 байт, приходит в виджет как `result`) |
| `editMessageWidgetData` | Изменить состояние одного сообщения: `chat_id` + `message_id` (или `inline_message_id`), `chat_data`, `public_data` |
| `editSharedWidgetData` | Изменить состояние общего виджета везде: `widget_id`, `public_data`, `cache_time` (5–3600 с) |

Инлайн-режим: статья с `InputWidgetMessageContent` (те же поля) или `InputSharedWidgetMessageContent` (`widget_id`). `copyMessage` для виджета запрещён, вместо него используй пересылку.

### Апдейты

Их нужно добавить в `allowed_updates`, иначе они не придут:

```json
{"allowed_updates": ["message", "widget_query", "shared_widget_query"]}
```

- `widget_query`: запрос из исходного сообщения. Поля: `id`, `from`, `chat` + `message_id` (или `inline_message_id`), `data`, а для общих виджетов ещё `widget_id`.
- `shared_widget_query`: запрос из копии общего виджета. Поля: `id`, `from`, `data`, `widget_id`.

**Отвечай на каждый запрос** через `answerWidgetQuery`, даже при ошибке. Запрос без ответа завершится в виджете с `TIMEOUT`.

### Правила правок

- Правка, которая ничего не меняет, падает с `message is not modified`. Считай это успехом.
- Применяй действие пользователя к своему состоянию **только после** успешной правки. Иначе при неудачной правке голос или ход потеряется.
- Храни в состоянии номер ревизии (`"r": 41`) и увеличивай его при каждой правке, чтобы виджет мог отбрасывать устаревшие состояния (см. `04-poll.html`).

### Минимальная отправка

```python
api("sendWidget", {"chat_id": chat_id, "html": open("widget.html").read()})
# width/height не указаны (= 0): ширина баббла, высота по содержимому
```

## Лимиты размера

- **32 768 байт** HTML и **4096 байт** после сжатия zlib уровня 9 (PHP `gzcompress($html, 9)`). Если больше, сервер вернёт `INPUT_MEDIA_WIDGET_TOO_LARGE`.
- Измеряй так же, как сервер:
  ```sh
  python3 -c 'import sys,zlib; print(len(zlib.compress(sys.stdin.buffer.read(), 9)))' < widget.html
  ```
  `gzip -9` показывает примерно на 12 байт больше. Рядом с лимитом верь числу из Python.
- Повторяющаяся разметка отлично сжимается, а `data:`-картинки почти не сжимаются. Генерировать повторяющиеся элементы небольшим циклом на JS (см. `03`) дешевле, чем выписывать их руками.

## Баббл: правила вёрстки

- **Ширина:** 200–600 px, на телефонах обычно **320–430 px**. `width: 0` (или не указано) означает ширину баббла, `W` — фиксированную ширину, обрезанную до максимума клиента. **Не рассчитывай на свою ширину:** дизайн шириной 320 px в баббле на 420 px оставит пустую полосу справа. Задавай фону `width: 100%`, а сцены фиксированного размера центрируй (`left: 50%; margin-left: -W/2`).
- **Высота:** `height: 0` означает высоту по содержимому в пределах [50, 600]. `H` означает фиксированную высоту clamp(H, 50, 600). Всё, что выше, обрезается, и внутри виджета ничего не скроллится.
- **Корневой элемент должен быть в обычном потоке.** Высота содержимого считается по потоку документа. Если у корня `position: absolute`, клиент насчитает примерно **50 px** и обрежет виджет. Используй у корня `position: relative` с явной высотой, а абсолютные элементы клади внутрь него.
- **У `body` есть отступ по умолчанию** — текстовый паддинг клиента (`--tg-text-padding`, около `8px 12px`). Без `body { margin: 0 }` всё сдвигается: слева и сверху видна полоса цвета баббла, а справа и снизу край обрезается.
- У `html` нет фона, поэтому просвечивает цвет баббла. Фон на `html`/`body` закрашивает весь баббл.
- **Время сообщения** рисуется поверх нижнего угла. Оставляй свободным `env(safe-area-inset-bottom)`: `padding-bottom: max(12px, env(safe-area-inset-bottom))`.
- **Тема:** используй `--tg-theme-bg-color`, `--tg-theme-text-color`, `--tg-theme-hint-color`, `--tg-theme-button-color`, `--tg-theme-button-text-color`, `--tg-theme-secondary-bg-color` и так далее. `prefers-color-scheme` следует теме **чата**.
- Без единиц `vh`. Используй px, %, flex или grid.

## Лимит отрисовки

**Одновременно не больше 16 «тяжёлых» элементов**, и из них не больше 2 с `backdrop-filter`. Если виджет выходит за лимит, рендерер его **останавливает** (`Paint limit exceeded: N boxes with shadows, filters or transparency (max 16)`). На устройстве это выглядит как пустой или чёрный баббл, либо как застывший кадр с плашкой «Widget stopped».

Элемент считается тяжёлым, если у него есть хотя бы одно из этого:

1. `opacity` **меньше 1, включая 0**;
2. любой `filter`, кроме `none` (включая `drop-shadow`);
3. любой `backdrop-filter`;
4. `box-shadow` с размытием больше 0;
5. **идущая анимация** `opacity`, `filter`, `backdrop-filter` или размытого `box-shadow`. Она считается всё время анимации, а `infinite` — всегда.

**Не** считаются тяжёлыми: анимации `transform`, `visibility`, элементы внутри `display: none`, тени без размытия, прозрачность выключенной или нажатой `<button>`.

Типичная ловушка: 12 мерцающих звёздочек с `@keyframes { opacity: 0 → 1 }`, плюс несколько полупрозрачных украшений, плюс буквы, которые проявляются из прозрачности. В сумме выходит больше 16, и виджет умирает на первом же кадре.

Как уложиться в лимит:

| Вместо | Используй |
|---|---|
| `opacity: .5` | цвета `rgba()` / `hsla()`; в SVG — `fill-opacity`, `stroke-opacity` |
| появление (`opacity 0 → 1`) | `transform: scale(0) → scale(1)` или выезд (`translate`) |
| исчезновение | уезд за обрезанную область или `scale(0)` |
| свечение через `filter: drop-shadow` / размытый `box-shadow` | `radial-gradient`, который уходит в прозрачность |
| анимированная тень | анимация `transform` у статичного элемента с градиентом |

Скрытое содержимое (`display: none`) ничего не стоит, пока его не покажут. Когда его показывают, его элементы начинают считаться.

## Что разрешено

Полный список — в `docs/profile-v1.md` репозитория widget-sandbox. Всё, что вне профиля, клиент **молча вырезает** и запускает остальное, поэтому виджет выглядит сломанным без всякой ошибки.

**Работает:** текст, списки, таблицы, `<details>/<summary>`, `<a>`, `<button>`, `<canvas>` (2D), `<img>` с `data:` PNG/JPEG/GIF/WebP (≤ 1024×1024), инлайн-SVG (фигуры, пути, текст, `<use>`, градиенты). CSS: flex, grid, позиционирование, скругления, градиенты, 2D-трансформации, transitions, `@keyframes`, CSS-переменные, `calc/min/max/clamp`, `:active`, `::before/::after`, `@media` (ширина, `prefers-color-scheme`, `prefers-reduced-motion`), `@supports`. Шрифты: только `system-ui`, `sans-serif`, `serif`, `monospace`, `ui-*`. JS: ES2023, таймеры, `requestAnimationFrame`, DOM, чтение лейаута, canvas 2D, Web Animations, `Intl`, `localStorage`/`sessionStorage`.

**Вырезается:** элементы форм (`input`, `select`, `textarea`…), `audio`/`video`, `iframe`, внешние `<script src>`/CSS/шрифты/картинки, `@font-face`, `@import`, `text-shadow`, `clip-path`, `mask`, `background-clip: text`, 3D-трансформации, `position: sticky`, `overflow: auto/scroll` (становится hidden), единицы `vh`, в SVG — `clipPath`/`mask`/`filter`/SMIL/`foreignObject`, `:focus`/`:checked`/`:has()`/`:target`, вложенность CSS, `@container`, `@layer`.

**Бросает исключение:** `fetch`, `XMLHttpRequest`, `WebSocket` (`NetworkDisabledError`). `alert`/`confirm`/`prompt`, `window.open`, буфер обмена и полноэкранный режим недоступны.

id элементов **не** становятся глобальными переменными. Используй `document.getElementById('x')`.

## Ввод

- `click` и pointer-события доставляются. **Тапы и двойные тапы всегда достаются виджету.**
- **Вертикальные свайпы всегда скроллят чат.** Забрать их нельзя.
- Удержание и горизонтальные свайпы забираются поэлементно через `touch-action`. При `auto` (по умолчанию) удержание открывает меню сообщения, а горизонтальный свайп — ответ. `pan-y` отдаёт виджету горизонтальные свайпы. `none` отдаёт виджету удержание и горизонтальные свайпы.
- Если нажатие забрал чат, виджет получает `pointercancel` и не получает `click`.
- Нет клавиатуры, фокуса, touch-событий (используй pointer) и событий колеса или скролла.
- Держи элементы управления не ближе 20 px к переднему краю: там системный жест «назад».

## JS SDK: `TelegramWidget`

`window.TelegramWidget` есть только внутри Telegram. **Всегда проверяй его наличие** (`if (window.TelegramWidget) …`): в браузере его нет.

```js
TelegramWidget.colorScheme;                 // 'light' | 'dark' (тема чата)
TelegramWidget.themeParams.bg_color;        // палитра
TelegramWidget.onEvent('themeChanged', fn); // также 'activated' / 'deactivated'
TelegramWidget.ready();                     // необязательно: первое состояние нарисовано
TelegramWidget.openLink('https://…');       // только в обработчике настоящего тапа; пользователь подтверждает
TelegramWidget.openTelegramLink('https://t.me/…');
TelegramWidget.copyText('PROMO');           // только в обработчике тапа
TelegramWidget.HapticFeedback.impactOccurred('light');
TelegramWidget.chatData; TelegramWidget.publicData;   // строки состояния (≤ 1024 Б) или null
TelegramWidget.onEvent('chatDataChanged', fn);        // и 'publicDataChanged'
TelegramWidget.request('vote:1');           // запрос к боту (см. ниже)
TelegramWidget.setResizeAnchor('bottom');   // расти вверх; по умолчанию 'top'
TelegramWidget.viewer; TelegramWidget.isForward; TelegramWidget.chatType; TelegramWidget.isPreview;
```

`TelegramWidget.sendMessage` **не существует**. Виджет никогда не пишет в чат сам, он может только попросить бота.

Привилегированные вызовы (`openLink`, `copyText`, `request`, кошелёк) работают **один раз на настоящий тап** и только внутри его обработчика (`click`/`pointerup`). Из таймеров, промисов и `pointerdown` они не работают.

## Состояние и запросы к боту

HTML после отправки **никогда не меняется**. Меняется только **состояние**, и пишет его только бот.

- `chat_data`: это сообщение в этом чате. В группе все видят одно и то же значение, пересылка его не получает. Подходит для идущей игры.
- `public_data`: показывается везде, где показан виджет. Пересылка получает снимок, общий виджет (`is_shared`) — одно живое состояние. Подходит для результатов опроса или цены.
- Оба поля — UTF-8 строки до 1024 байт, обычно JSON.
- Для живого общего состояния виджет вызывает `TelegramWidget.watchPublicData()`, и клиент опрашивает его, пока виджет на экране.
- `localStorage`: на сообщение и устройство, 4 КБ на область. Для личного выбора пользователя. Пересланная копия начинает с пустого хранилища.

**Цепочка запроса** (`04-poll.html` + `bot.py`):

```
виджет (тап)  request('vote:2')                         data: 1–64 байта
   └─> бот    update.widget_query {id, from, chat, message_id, data}
        ├─ editMessageWidgetData(public_data=…)        -> виджет получает publicDataChanged
        └─ answerWidgetQuery(widget_query_id=id, data=JSON) -> промис резолвится {result}
```

Промис отклоняется с `err.code`, равным одному из: `NOT_ALLOWED` (нет тапа, отправлено без `allow_queries` или пересылке нельзя), `BUSY` (один запрос за раз), `RATE_LIMITED`, `TIMEOUT` (бот не ответил), `FAILED`, `INVALID_ANSWER`. Обрабатывай в интерфейсе каждый код.

В личке с ботом `request` может работать и без тапа: один раз при появлении виджета, затем не чаще раза в 5 с, пока он виден. В группах, через инлайн-режим и в пересылках — только по тапу.

## Лимиты рантайма

| Ресурс | Лимит |
|---|---|
| CPU | 300 мс в секунду; одна задача ≤ 500 мс, иначе виджет останавливается |
| Нагрузка на главный поток (чтение лейаута + ~25 мкс на изменение DOM) | 100 мс в секунду |
| Память | 8 МБ |
| Узлы DOM | 2000 |
| CSS | 400 правил, 32 `@keyframes` |
| Таймеры | 64 активных |
| Чтений лейаута за задачу | 128 |
| Canvas | 2048×2048 px всего; 4000 команд на canvas за задачу |
| Тяжёлые элементы | 16 (2 с `backdrop-filter`) |

За пределами экрана нет кадров анимации, а таймеры срабатывают не чаще раза в секунду. Виджет могут уничтожить и пересоздать в любой момент; сохраняются только Web Storage и состояние виджета.

## Тестирование

1. **Размер и линт** (мгновенно, без зависимостей):
   ```sh
   python3 tools/check_widget.py my-widget.html
   ```
2. **Официальная песочница** — настоящие валидатор и рендерер. Она ловит лимит отрисовки, вырезанные фичи и высоту:
   ```sh
   git clone https://github.com/TelegramMessenger/widget-sandbox && cd widget-sandbox
   npx pnpm@12 install
   cd packages/core && npx pnpm@12 tsx scripts/sandbox-node.ts /путь/к/widget.html
   #   --width 360 дополнительно раскладывает виджет и печатает строку `paint:` (нужен `npx playwright install chromium`)
   #   --tap x,y / --hold x,y / --swipe x,y,dx,dy проверяют жесты
   ```
   Dev-приложение (`cd apps/web && npx pnpm@12 exec vite`, затем `http://127.0.0.1:5173/?file=<путь в corpus>`) показывает баббл, статус (`loaded` или `sandbox terminated: …`), высоту баббла, диагностику и панель мок-бота. Файл должен лежать внутри `corpus/`, иначе его не будет в списке.
   Если `corepack pnpm` падает с `Cannot find module …/pnpm.cjs`, используй `npx pnpm@12`, как выше.
3. **Настоящее устройство.** Отправь виджет себе, в группу, через инлайн-режим и перешли его: в каждом месте у виджета разные права. Просмотра в десктопном браузере **недостаточно**: Chrome спокойно рисует то, что рендерер Telegram останавливает или вырезает.

## Диагностика проблем

| Симптом | Причина | Что делать |
|---|---|---|
| `sendWidget` → `Not Found` | Обычный адрес API | Используй `https://api.telegram.org/beta` |
| `parameter "html" is required` на пустом вызове | Так и должно быть | Метод есть, отправляй настоящие данные |
| `INPUT_MEDIA_WIDGET_TOO_LARGE` | > 32 КБ или > 4 КБ после zlib-9 | Генерируй повторы на JS, сокращай классы, убери `data:`-картинки |
| Пустой или чёрный баббл, либо застывший кадр / «Widget stopped» | Лимит отрисовки (> 16 тяжёлых), лимит CPU/памяти или падение | Прогони через песочницу; замени `opacity`/`filter`/размытые тени; см. [Лимит отрисовки](#лимит-отрисовки) |
| Полоса слева/сверху, справа/снизу обрезано | Отступ `body` по умолчанию | `body { margin: 0 }` |
| Пустая полоса справа | Фиксированный дизайн на 320 px в баббле шире | `width: 100%` + сцена по центру |
| Виджет обрезан до ~50 px по высоте | Корень с `position: absolute`, высота потока 0 | Корень в обычном потоке (`position: relative` + высота) |
| Анимация не играет / элемента нет | Фича вне профиля, молча вырезана | Сверься с `profile-v1.md`; смотри строки `diag` в песочнице |
| `request()` → `NOT_ALLOWED` | Отправлено без `allow_queries`, нет тапа или это пересылка | `allow_queries: true`; вызывай внутри `click` |
| `request()` → `TIMEOUT` | Бот не вызвал `answerWidgetQuery`, или `widget_query` нет в `allowed_updates` | Всегда отвечай; подпишись на апдейт |
| Правка падает с `message is not modified` | Состояние не изменилось | Считай успехом |
| В Chrome работает, в Telegram сломано | Chrome — не тот рендерер | Тестируй в песочнице и на устройстве |

## Чеклист перед отправкой

- [ ] `body { margin: 0 }`, корень в обычном потоке, `width: 100%`, без `vh`
- [ ] ≤ 16 тяжёлых элементов **в любой момент**: нет `opacity` < 1, `filter` и размытых теней на множестве элементов; анимации только через `transform`
- [ ] ≤ 32 КБ / ≤ 4 КБ после zlib-9
- [ ] только системные шрифты; никаких внешних ресурсов и сетевых запросов
- [ ] наличие `TelegramWidget` проверяется; привилегированные вызовы только в обработчиках `click`
- [ ] нижний угол свободен под время (`env(safe-area-inset-bottom)`)
- [ ] используются переменные темы, проверено в тёмной и светлой теме чата
- [ ] бот: бета-адрес, `widget_query` в `allowed_updates`, ответ на каждый запрос, `not modified` считается успехом
